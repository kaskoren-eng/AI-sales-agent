2. **~~Fixed a lead-capture regression.~~ RETRACTED — there was no regression.** This section
   originally claimed the 08-29 deploy had dropped `data-netlify="true"` and
   `netlify-honeypot="bot-field"` from both demo forms, and that leads had been silently lost
   since. **That was wrong**, and it was told to Koren before it was checked properly. The claim
   is left visible rather than deleted so nobody re-derives it from the same evidence.

   **What is actually true:** Netlify's form-detection parser consumes those two attributes at
   deploy time and **strips them from the served HTML**, re-serializing the `<form>` tag with
   single quotes and reordered attributes. So production serves
   `<form action='/thanks' data-demo-form method='POST' name='demo-en'>` while being entirely
   healthy. The single-quote "re-serializer fingerprint" is Netlify itself, not the
   accessibility tooling.

   **How it was settled:** production was redeployed from `main`, whose HTML demonstrably
   contains `data-netlify="true"` — and the served output, on both the production URL and that
   deploy's unique URL, came back stripped exactly as before. `Downloads\clickscales-website-deploy`,
   the folder dragged in *before* the accessibility work, also contains the attribute, so the
   live HTML has looked like this since forms were enabled on 2026-07-29. There was never a
   moment of regression to find. `listSiteForms` confirms both forms registered with their
   parsed field lists and `honeypot: true` — which Netlify can only know by having read
   `netlify-honeypot="bot-field"`.

   **Rule for next time:** before calling a missing attribute a regression, ask whether the
   platform is supposed to consume it. For a form directive on Netlify, the answer is yes.

   Netlify API says `demo-en` has 2 submissions ever, last **2026-08-28 08:32**, and `demo-he`
   has 0 ever. That is low traffic, not a fault — and the 08-28 submission is itself end-to-end
   evidence that a lead can land. Submitting the live form once remains the only way to close
   the question completely, and it writes a real row, so it is Koren's call.
