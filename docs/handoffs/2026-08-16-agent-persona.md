# 2026-08-16 — Phase 3: per-tenant agent identity

Workstream: DASHBOARD (page) + VOICE (prompt/greeting/TTS). Branch: `main`.

## What shipped

The agent's identity is no longer a set of hardcoded strings. `tenants.settings.agent_persona`
now drives the prompt's Role section, the Hebrew gender rules, the FAQ table, the opening line, the
voicemail message and the TTS voice — and the Agent Personality page in the dashboard finally
writes to something.

New: `src/modules/channels/voice-livekit/persona.ts` — `AgentPersona`, `DEFAULT_PERSONA`,
`readAgentPersona()`, `buildGreeting()`, `renderIdentity()`, `renderFaq()`, `isDefaultPersona()`.

API: `GET/PUT /api/v1/settings/agent-persona`.

Dashboard: `AgentPersonality.tsx` rebuilt (was 244 lines of `useState` with zero API calls).

Tests: 710 → 739.

## The safety property, and why it is the important part

`__fixtures__/prompt-default-*.txt` were generated by running the PRE-CHANGE file, extracted with
`git show HEAD:…` before the edit landed — not by snapshotting the new output. Four tests assert
the default persona reproduces them byte for byte. **ClickScales' live agent runs the identical
prompt and the identical greeting**, which is what made this shippable without re-running the
voice A/B suite.

If one of those tests fails, the question is never "update the fixture".

## Five leaks found while doing it — four of them not on the plan

The plan named the Role section, the gender rules and the founder FAQ. A blanket "no ClickScales
string may appear in a custom tenant's prompt" test found the rest:

1. **The voicemail message** (`call-state-lines.he.ts`) — "שלום, מדברת קרן מ-ClickScales…", left
   ON the lead's phone. The one identity mistake that outlives the call.
2. **The objection playbook** — "שיחת הדמו הקצרה עם קורן".
3. **The security rules** — "not claiming to work for ClickScales". An impersonation defence that
   names the wrong company is not a defence.
4. **The Step 3 mindset rebuttal** — "explain that ClickScales builds agents that sound human" is a
   claim about ClickScales' product, and nonsense for a garage.
5. **The default FAQ inherited by a renamed agent** — my own first version of `readAgentPersona`
   did this. Renaming the agent kept all six rows, including "קורן הוא המייסד של ClickScales".
   Fixed by tying each ClickScales-specific default to the thing it describes: name-specific
   defaults drop when the name changes, company-specific ones when the company does.

## Two bugs fixed that were not identity bugs

- **`buildToolRuntime` discarded the settings whenever the gate closed.** A tenant with
  `functions_enabled: false` — or no calendar credentials — got `runtime: null`, and with it
  ClickScales' entire persona. The result type now carries `settings` on every path, and the
  calendar-credential check moved to AFTER the settings read (the ordering fix the Phase 4 plan
  flagged, needed here for the same reason).
- **`saveAgentPersona` let a smuggled `tts` through** when none was stored. Caught by its own test.
  The patch is now stripped, not merely overwritten.

## Decisions worth knowing

- **Voice is operator-managed.** Cartesia and ElevenLabs return a *silent stream* for a bad
  `voiceId`, not an error, so a tenant cannot type one. The typed route has no `tts` field.
- **The greeting is generated, not stored,** unless the tenant writes their own. A stored line
  would out-rank a later rename and the agent would keep introducing itself by the old name.
- **`persona.companyName` is explicit, not derived from `businessProfile.companyName`.** Deriving
  it would have silently changed what ClickScales' live agent says the day this deployed.
- **Per-tenant TTS is constructed only when it differs from the default,** so customer #1 runs
  byte-for-byte today's code path — the component whose latency is most heavily tuned.
- **`CallReport.updateConfig()` is new** (the plan assumed it existed). Without it a custom-voice
  call files its latency numbers under the platform default voice.

## What I cut from the dashboard page, and why

- **The metrics strip** ($0.08/min, 1.2s, "Sonic · עברית"). Cost per minute has never been
  measured — `docs/gtm/pricing-model.md` says so — and 1.2s was typed, not read. Invented numbers
  on a customer-facing dashboard get quoted back at you.
- **The eight behaviour switches** (filler words, empathy, short answers, confirm details, say
  numbers simply, AI disclosure, recording notice). Nothing in the agent reads any of them. Wiring
  them to a settings key the prompt ignores would be worse than leaving them dead. Each needs
  prompt work and a real call — content work, not plumbing.

Replaced by the thing they were decoration around: the sentence a lead actually hears, live, as you
type. Verified in-browser — one gender toggle flips both `מדבר`/`מדברת` and `יכול`/`יכולה`.
