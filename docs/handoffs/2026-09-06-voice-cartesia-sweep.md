## The proof, run and pasted

This branch is supposed to change no behaviour. You cannot mutation-test a comment, so the check
that can actually fail here is the diff filter. Filtering every line that is not a comment out of
the TypeScript/JS diff:

```
$ git diff -U0 origin/main...HEAD -- '*.ts' '*.mjs' \
    | grep -E '^[+-]' | grep -vE '^(\+\+\+|---)' | grep -vE '^[+-]\s*(//|/\*|\*)'
<<< no output >>>
```

Empty. Every `+`/`-` line in the `.ts` diff is a `//`, `/*` or ` *` line. The rest of the diff is
`.env.example` (`#` comment lines) and `README.md` (prose). No identifier, literal, condition or
import moved.

**One edit was reverted to keep that true.** `testing/scenarios.ts` has a scenario
`description:` string that reads *"The comma/ellipsis makes Cartesia actually pause mid-utterance"*.
It is stale in exactly the target way, but it is a string literal, not a comment, and it showed up
in the filter. I backed it out rather than weaken the proof. It is listed under **Left for a human**
below — it wants one line changed on a branch that is allowed to touch code.

## Left for a human — reasoning, not wording

These are places where the comment's *conclusion* rests on a Cartesia measurement and the code runs
on DeepDub. I marked each as unverified rather than rewriting it to assert the conclusion still
holds. **None of these is a known bug. Each is a claim nobody has re-checked since 2026-09-02.**

1. **`synthetic-caller.ts:290` — the harness's speech detector rests on a Cartesia premise.**
   The code is `if (isSilent(frame)) continue;` guarded by *"Cartesia never emits digital silence
   mid-utterance, so any non-silent frame is speech."* That premise is about Cartesia and the
   harness now synthesizes through whatever `VOICE_TTS_PROVIDER` names. If DeepDub emits true
   digital silence between words, this under-counts agent speech and every timing the synthetic
   caller reports drifts — silently, and in the direction that looks like a faster agent. **The
   highest-value item here**, because it is an instrument, and a broken instrument returning the
   comfortable answer is this repo's recurring failure. Cheap to settle: dump frames from one
   DeepDub synthesis and look for zero-runs.

2. **`speech-guard.ts` niqqud strip — safe, but justified by a Cartesia number.** The strip exists
   because full pointing was distorted on Cartesia (§13, 2026-08-26). It is fail-safe in either
   direction, so I left it and said so. But the *positive* half is not fail-safe: `PRONUNCIATION_FIXES`
   re-injects verified single marks (שלךָ, לוודֵא) **after** the strip, and every one of those marks
   won its round on Cartesia. Whether DeepDub needs them, ignores them, or is made *worse* by them is
   unknown. This is the one item that can currently be affecting what a lead hears.

3. **`dictation.ts` — the exemption's whole justification is a Cartesia clip.** Unpointed `אמ.` was
   0.16s of near-silence on Cartesia, which is why `stripNiqqudExceptOwnSounds` exists. If DeepDub
   renders it audibly, the exemption is now protecting nothing; if DeepDub renders the *pointed*
   `אֶמ.` badly, it is actively hurting. Same for the round-10 filler bank
   (`thinking-fillers.he.ts`) and the `אהה`→`אמ` acknowledgement decision.

4. **`system-prompt.he.ts:214` — the emotion section.** *"Cartesia's emotion tags do NOTHING on
   Hebrew … what DOES change delivery is the TEXT itself: sonic reads emotional subtext from wording
   and punctuation."* The verdict is dated and correct as history, and I left the whole section
   alone. But **the ban on written laughter and the chosen devices (אוף / איזה כיף / וואלה) were all
   screened on sonic**, and the surviving mechanism is explicitly *"sonic reads emotional subtext"*.
   Whether DeepDub reads subtext the same way is a prompt-content question, not a comment question.

5. **`call-report.ts:582` — `spread` has no threshold on the live engine.** Cartesia's take-to-take
   variation was ~2x, which is why the field says a 7% deliberate change is unprovable on one call.
   DeepDub's variation has never been measured, so the number is currently readable but not
   judgeable. Noted in the comment; needs one bench run, not a decision.

6. **`testing/scenarios.ts:38` — the one string literal I did not touch.** Its `description` says
   the comma/ellipsis *"makes Cartesia actually pause mid-utterance"*. Stale, and whether DeepDub
   honours the same punctuation is unverified. Reverted here to keep the comment-only proof clean;
   one line, needs a branch allowed to change code.

7. **`agent.config.ts:224` — a genuine code bug, found while reading, NOT fixed here.**

   ```ts
   ...(override.voiceId
     ? override.provider === 'elevenlabs'
       ? { ELEVENLABS_VOICE_ID: override.voiceId }
       : { CARTESIA_VOICE_ID_PRIMARY: override.voiceId }
     : {}),
   ```

   A tenant persona with `provider: 'deepdub'` and a `voiceId` writes that id into
   `CARTESIA_VOICE_ID_PRIMARY`, which `deepdubOptions()` never reads — it reads
   `DEEPDUB_VOICE_PROMPT_ID`. The tenant's chosen voice is silently ignored and the platform default
   voice speaks. This is the operator-managed setting `persona.ts` warns about, on the default
   engine, and it is invisible in every log. **Harmless today** because no tenant has a `tts`
   override (`buildTTS`'s own comment says "which is every call today"), so it is latent, not live.
   Out of scope for a comment branch — flagging rather than fixing, per the brief.

8. **`generate-system-announcements.mjs` — a product observation, not a bug.** The DID-refusal
   announcement is pre-rendered by Cartesia ("Noam - Broadcaster") while the agent speaks DeepDub.
   Deliberate — the announcement is *meant* to sound unlike the agent — but it means a full Cartesia
   decommission would need this script re-pointed, and it means `CARTESIA_API_KEY` stays a real
   dependency of the repo even if the engine never comes back. Worth Koren knowing before anyone
   proposes deleting the Cartesia account.
