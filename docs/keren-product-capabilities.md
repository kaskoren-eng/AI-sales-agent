# קרן — קטלוג יכולות המוצר
## Keren Product Capabilities Spec — what a business gets when they buy Keren

**העיקרון המארגן:** קרן היא המוצר ש-ClickScales מוכרת לעסקים. כל יכולת נבנית **per-tenant**: הלקוח מחבר את הכלים *שלו* (היומן שלו, ה-CRM שלו, החשבוניות שלו), וקרן עובדת בשבילו — מכירות ושירות.

**ClickScales עצמה = tenant #1 (dogfooding).** כל מה שנבנה לקורן נבנה גנרי.

---

## 1. ערוצי תקשורת (Channels)

| ערוץ | סטטוס | מה הלקוח מקבל |
|---|---|---|
| 📞 שיחות נכנסות | ✅ עובד | קרן עונה למספר של העסק (Zadarma SIP → LiveKit), מסננת, מתאמת |
| 📞 שיחות יוצאות | ✅ עובד (טסט) | קרן מתקשרת ללידים חדשים של העסק |
| 💬 וואטסאפ | ✅ זמני דרך Twilio | אישורים, תזכורות, מעקבים. **מצב ביניים:** הוואטסאפ העסקי ממתין לאישור Meta — עד אז Twilio WhatsApp משמש כגשר. אחרי אישור: מעבר ל-Meta Cloud API ישיר |
| 📧 מייל | ✅ תשתית קיימת | אישורים ומעקבים מהדומיין של הלקוח |

**חלוקת ספקי תקשורת:** Zadarma = טלפוניה (SIP). Twilio = וואטסאפ זמני + ניטור שיחות ועידה בלבד. לא להתבלבל ביניהם.

## 2. יכולות מכירה (Sales)

### 2.1 סינון וכישור לידים ✅ (עובד)
- שאלות discovery מותאמות לעסק של הלקוח (מה-Business Profile שלו)
- ניקוד HOT/WARM/COLD לפי קריטריונים של הלקוח
- שמירת נתוני הכישור ל-CRM של הלקוח בזמן אמת

### 2.2 קביעת פגישות ✅ (Priority 1 הושלם)
- בדיקת זמינות **ביומן של הלקוח** וקביעה עם הזמנה + Meet link
- ⚠️ **פער מוצרי לסגור:** היום Google Calendar מחובר ב-service account של ClickScales. מוצרית נדרש **OAuth per-tenant** — כל לקוח מחבר את היומן שלו בקליק (מסומן ב-THIRD_PARTY_REPORT כ-fix נדרש)
- שעות עסקים מוגדרות per-tenant (לא hardcoded ראשון-חמישי 09:00-17:00 — זו ברירת מחדל)

### 2.3 תזכורות פגישה 🔜 (Workstream C1)
- וואטסאפ + מייל, יום לפני ושעה לפני, ביטול אוטומטי בשינוי
- תבניות הודעה מותאמות לטון של העסק (מה-Business Profile)

### 2.4 פולואפים — מוגדרים אבל גמישים 🔜 (Workstream C2)
- ספריית flows מוכנים: לא-ענה / ביקש-callback / לא-הגיע-לפגישה / אחרי-הצעה / ליד-פושר
- כל flow הוא **config per-tenant** (`tenants.settings.flows`) — הלקוח (או ClickScales עבורו) מכוונן תזמונים, ערוצים וניסוחים בלי קוד
- שעות שקט, opt-out, וגבולות חוקיים — נאכפים ברמת המערכת, לא ניתנים לעקיפה

## 3. יכולות שירות (Service)

### 3.1 מענה על שאלות נפוצות ✅ חלקי
- FAQ מוגדר per-tenant בפרומפט (שעות פעילות, מחירים שמותר לומר, שירותים)
- 🔜 שדרוג עתידי: Knowledge Base מקבצים (RAG) — הלקוח מעלה מסמכים

### 3.2 העברה לאנוש ✅ (Priority 1)
- זיהוי בקשה לנציג → הודעה לבעל העסק / transfer
- כללי אסקלציה per-tenant (מתי מעבירים, למי)

### 3.3 עדכוני סטטוס ותיעוד 🔜 (Workstream B)
- כל שיחה מתועדת: תמליל, סיכום GPT, תוצאה — נדחף ל-CRM של הלקוח

## 4. חיבורי כלים (Integrations) — הלקוח מחבר את שלו

### 4.1 CRM — עדכון סטטוסים + סיכומי שיחה

| כלי | סטטוס | הערות |
|---|---|---|
| **Monday.com** | ✅ אינטגרציה מלאה קיימת | sync/push/webhook, טוקן per-tenant מוצפן |
| **Airtable** | ✅ קיימת | |
| **Fireberry** | 🔜 לבנות | ה-CRM הישראלי הנפוץ — קריטי לשוק היעד. נבנה לפי תבנית Monday |
| Google Sheets | ⚠️ חלקי | להשלמה בהמשך |
| HubSpot ואחרים | 🔮 עתידי | לפי דרישת לקוחות; webhook גנרי (Make/Zapier) כגשר |

**מה קרן עושה עם ה-CRM:** יצירת ליד, עדכון סטטוס אחרי כל שיחה, סיכום שיחה כ-note, נתוני כישור בשדות.

### 4.2 יומנים

| כלי | סטטוס |
|---|---|
| **Google Calendar** | ✅ עובד — נדרש מעבר ל-OAuth per-tenant |
| Trafft | ✅ provider קיים |
| Outlook/Microsoft 365 | 🔮 עתידי לפי דרישה |

### 4.3 חשבוניות ומסמכים

| כלי | סטטוס | הערות |
|---|---|---|
| **SUMIT** | 🔜 לבנות במקביל | הספק של ClickScales (tenant #1) |
| **חשבונית ירוקה** | 🔜 לבנות במקביל | הספק של רוב הלקוחות הישראלים — **דרישת השקה למכירת קרן** |
| iCount ואחרים | 🔮 עתידי | ה-interface מאפשר הוספה זולה |

שניהם נבנים מאחורי provider interface אחד; כל tenant בוחר את הספק שלו ב-settings.

**מה קרן עושה:** הפקת חשבונית מס/קבלה ללקוח ששילם + שליחה במייל. טריגר: פעולה של בעל העסק או webhook תשלום — **לא מתוך שיחה** (קרן לא מדברת על כסף).

## 5. Onboarding של לקוח חדש (החוויה המוצרית)

זרימת חיבור שהופכת עסק ללקוח פעיל:

```
1. Business Profile — שאלון/שיחה: מה העסק, מה מוכרים, קהל יעד, טון,
   התנגדויות נפוצות, קריטריוני כישור  →  מוזרק לפרומפט של קרן
2. חיבור יומן        — OAuth בקליק (Google)
3. חיבור CRM         — הדבקת טוקן (Monday/Airtable/Fireberry)
4. חיבור וואטסאפ     — מספר העסק
5. חיבור חשבוניות    — טוקן SUMIT/חשבונית ירוקה (אופציונלי)
6. בחירת flows       — הפעלת פולואפים מהספרייה + כוונון
7. מספר טלפון        — הקצאה/העברה
8. שיחת בדיקה        — בעל העסק מתקשר ומאשר
```

כבר קיים בקודבייס: tenants API, טוקנים מוצפנים, flow config storage. חסר: UI self-serve (Phase 6 המקורי) — בינתיים ClickScales עושה onboarding מלווה (concierge), שזה נכון עסקית בהתחלה.

---

## 6. עקרונות בנייה (לכל פיצ׳ר חדש)

1. **Per-tenant מהקומיט הראשון** — אף credential, לוח זמנים, או ניסוח לא hardcoded. הכל מ-`tenants.settings` / טבלאות per-tenant.
2. **הלקוח מביא מפתחות משלו** — CRM, יומן, חשבוניות, וואטסאפ = של הלקוח. ClickScales משלמת רק על התשתית (LiveKit, STT/TTS/LLM).
3. **Provider interfaces** — יומנים, חשבוניות, CRM: interface אחד, מימושים מתחלפים. הוספת ספק = מודול, לא שכתוב.
4. **גבולות בטיחות ברמת מערכת** — opt-out, שעות שקט, toll fraud limits, tenant isolation — נאכפים בקוד, אף tenant לא יכול לעקוף.
5. **הפרומפט מודולרי** — בסיס משותף (כללי דיבור, אנטי-הזיה, compliance) + שכבת Business Profile של הלקוח.

## 8. הדאשבורד התפעולי של הלקוח (Client Control Panel)

**המטרה:** הלקוח מתפעל את קרן בעצמו — מגדיר חיבורים, מכוונן פולואפים, רואה מה קורה. זה ההבדל בין ״שירות שמנהלים בשבילי״ ל**מוצר SaaS**.

**הערה ארכיטקטונית:** ה-`dashboard/` הקיים (overview/leads/calls/flows) הוא הבסיס — מרחיבים אותו, לא בונים מאפס. שני קהלים באותו דאשבורד: הלקוח (tenant) רואה רק את שלו; ClickScales admin רואה הכל.

### מפת המסכים

**🏠 Overview (קיים — להרחיב)**
- KPIs של העסק: שיחות היום/השבוע, פגישות שנקבעו, אחוז מענה, לידים חמים
- פיד פעילות אחרונה: ״קרן קבעה פגישה עם יובל מחר ב-11:00״
- התראות: חיבור שנפל, פגישה שבוטלה, ליד חם שממתין

**🤖 My Agent — ״אמן את קרן״ (חדש — הלב של המוצר)**
- Business Profile בטופס ידידותי: מה העסק, מה מוכרים, קהל יעד, טון דיבור, התנגדויות נפוצות, קריטריוני כישור (תקציב/טיימליין)
- FAQ editor: שאלות ותשובות שקרן רשאית לענות
- כללי אסקלציה: מתי להעביר לאנוש, למי, באיזה ערוץ
- בחירת קול (מספריית הקולות העבריים) + האזנה לדוגמה
- **כפתור ״שיחת בדיקה״** — הלקוח מתקשר לקרן ובודק את השינויים לפני הפעלה
- כל שינוי = version history (יש כבר תשתית ל-prompt versioning)

**🔌 Integrations (חדש)**
- כרטיסים לכל כלי: Google Calendar / Monday / Airtable / Fireberry / SUMIT / חשבונית ירוקה / וואטסאפ
- לכל כרטיס: סטטוס (מחובר/לא/שגיאה), כפתור Connect (OAuth או הדבקת טוקן), בדיקת חיבור, ״נבדק לאחרונה״
- Mapping UI ל-CRM: איזה board/base, איזה עמודות = סטטוס/טלפון/סיכום

**⚙️ Workflows (הרחבת עמוד flows הקיים)**
- **תזכורות פגישה:** מתגים + תזמונים (יום לפני / שעה לפני / מותאם), בחירת ערוצים, עריכת נוסח ההודעה עם preview
- **ספריית פולואפים:** כרטיס לכל flow (לא-ענה, no-show, אחרי-הצעה, ליד-פושר) — הפעלה/כיבוי, כוונון delays וניסוחים, תצוגת timeline ויזואלית של הרצף
- **גבולות מערכת (read-only ללקוח):** שעות שקט, opt-out — מוצגים אבל לא ניתנים לכיבוי

**📞 Calls (קיים — משודרג ב-Phase 5)**
- רשימת שיחות עם האזנה, תמליל, סיכום, תוצאה
- ״למה קרן עשתה X?״ — הצגת ה-tool calls בשפה פשוטה

**👥 Leads (קיים)**
- סטטוסים, נתוני כישור, timeline רב-ערוצי per lead

**💳 Billing & Docs (חדש, שלב מאוחר)**
- חשבוניות שהופקו, טריגר ידני ״הפק חשבונית״, סטטוס שליחה
